# Crossroads v0.3 — 밸런스 및 플레이 경험

2026-10-27. 기존 미커밋 작업은 backups/v0.3-before에 복사하고 추적 파일 diff도 보존한 뒤 증분 수정했다. Git 커밋·푸시·공개 배포는 수행하지 않았다.

## 1. 변경 전 진단

실제 등록 159개(메인 55, 조건부 25, 위기 9, 일상 45, 교체 6, 자유 운영 정책 19)를 분석했다. 원본 카드 파일 6개의 바이트는 그대로 보존한다. 등록 단계에서 3개 선택 효과와 46개 발언을 선별 적용한다. 역할 변경은 [별도 보고서](v0.3-character-roles.md)와 [159개 판정표](v0.3-character-audit.md)에 기록한다.

- 높은 자원 하나가 95에 도달하면 위기를 여는 규칙 때문에, 한 위기를 해결한 보상이 다른 높은 자원의 위기를 열었다. 왼쪽·오른쪽 고정과 최저 자원 보호 전략 모두 1,000개 시드에서 ACT I을 400단계 안에 끝내지 못했다. 보충 1회 2,000단계 진단에서도 같은 현상을 재현했다.
- 즉시 효과 합계는 왼쪽에서 신뢰·공정·자유가 크게 늘고 오른쪽에서 감소했다. 안전은 반대였다. 단순히 모두 승인/거부하는 것은 서로 다른 가치에 편향된 선택이다.
- 4자원 즉시 효과만 비교하면 한쪽이 다른 쪽을 모두 앞서는 카드가 6개였다. 다른 주제라도 자원 벡터가 같은 카드가 있으며, 플래그·관계·후속 사건까지 같다는 뜻은 아니다.
- 기본 표정도 작은 표정 칸을 사용하거나 70×96 이미지를 145×180으로 확대해 얼굴이 흐려졌다.

## 2. 실제 엔진 시뮬레이터

재현 명령: `npm run simulate -- 1000 v0.3-final`. 변경 전 수치는 수정 전 엔진으로 먼저 실행하여 보관했다. [변경 전 원시 결과](simulations/v0.2-baseline.json), [최종 원시 결과](simulations/v0.3-final.json).

- 각 전략 1,000회, 8전략 합계 8,000회. 전·후 비교 총 16,000회다. 개발 도중의 중간 측정은 최종 비교에 포함하지 않는다.
- 시드 i×97, i=1…1000. 카드 추첨은 실제 엔진 RNG, 무작위 플레이어 선택은 별도의 고정 시드 RNG다.
- 매 실행은 실제 새 게임 상태에서 시작한다. 화면과 같은 transitionSession의 decision → requestAct2 → confirmAct2 → enterFreePlay를 사용한다. startAct2 직접 호출이나 성공 상태 삽입으로 우회하지 않는다.
- 우선 전략은 좌·우 선택을 실제 엔진으로 각각 미리 계산한다. 목표 자원×10 + 다른 자원의 25 이하 구간 보호를 평가하고, 감독관 교체로 얻는 복구를 점수로 악용하지 않도록 교체 시 2,000점을 차감한다. 동점은 고정 시드로 선택한다. 미래 사건을 탐색하는 전지적 최적해는 아니다.
- 자유 운영 진입일로부터 100일을 진행한다. 최대 400회 전환 후 미완료면 제한 도달로 집계한다. 즉시 진행 거부(stalls)와 반복·과다 지연에 따른 제한 도달(limits)은 따로 기록한다.
- 화면 전환마다, 그리고 100번째 판단마다 실제 migrateGameState로 JSON 저장을 복원하여 계속 플레이한다. 자원·기록·관계·비밀·ACT·모드·카드·RNG·예약의 불변식을 검사한다.
- 자원 평균은 초기값과 모든 실제 선택 정산 후 값의 관측 가중평균이다. 회차별 평균의 평균이 아니다. 완료하지 못한 변경 전 전략과 노출 기간이 다르므로 평균만으로 난이도를 단정하지 않는다. 교체 전 최솟값도 별도 보존한다.

## 4. 수정한 로직과 카드

- detectResourceCrisis: 95 이상만으로는 위기를 만들지 않는다. 신뢰↑+공정≤20, 공정↑+안전≤20, 자유↑+안전≤20, 안전↑+자유≤20일 때 기존 불균형 사건을 사용한다. 모든 자원이 높으면 위기는 없다. 10 이하 붕괴와 복합 위기 기준은 유지한다.
- executeDecision: 즉시·지연 효과를 정산한 뒤 위기를 평가한다. 불균형의 원인이 해소되면 높은 수치가 그대로여도 해당 위기를 해결한 것으로 기록한다. 첫 위기 대응 실패로 0이 되더라도 두 번째 대응 기회를 보장하고, 두 차례 같은 위기 미해결 후 교체한다. 일반 정책 선택에서 자원이 0이 되는 기존 직접 불신임 조건은 유지한다.
- selectNextCard/municipalWeight: 40 미만 자원을 개선할 선택이 있는 안건의 추첨 비중을 최대 3배로 올리되 다른 안건도 남긴다. 직전 화자는 가능한 경우 제외하고 그 전 화자는 비중을 낮춘다. 조건부·예약·메인 순서와 메인 사이 최대 2회 사건 규칙은 보존한다.
- 카드 풀이 부족하면 쿨다운을 줄이지 않는다. minDay와 조건을 만족할 수 있는 다음 날짜로 대기하고 예약·선택 진단도 갱신한다.
- migrateGameState: schemaVersion 5를 유지한다. 구버전 v5의 고자원 단독 위기는 새 규칙으로 재평가하되 자원·결정·ACT를 초기화하지 않는다. 저장 키와 기존 이력은 보존한다.

## 5. 테스트 및 실제 UI 확인

- 자동 테스트 36개 통과: 기존 24개 + 새 12개. 기존 고자원 경계 테스트 2개는 새 해로운 불균형 조건으로 갱신했다. 원본 140개 바이트 보존 검사는 계속 통과한다.
- 신규 검증: 재현성, 8전략 양 ACT·100일, 자원 0~100, 고자원 단독 위기 방지, 실패한 첫 대응의 두 번째 기회·구제·교체, v5 저장, 풀 고갈, 상태 반응 추첨, 159개 데이터 보존, 대사 분기, 잘못된 직함, 19개 정책 후속, 표정 에셋 출력.
- 타입 검사 통과, 프로덕션 빌드 통과. 초기 JS 약 589kB로 500kB 경고는 남는다.
- 콘텐츠 진단: valid=true, errors=[]; 메인 55개 전부 도달. 기본 진단의 단일 경로에서는 145개만 등장했다. 나머지는 분기·위기 경계 회귀 검사와 대규모 측정으로 확인했다.

## 6. 남은 문제와 추가 설계

1. 최저 자원 보호 전략의 위기·교체는 0이고 네 자원 평균이 87~93이다. 현재 모델에서는 이상적 선택으로 높은 자원을 유지하기 쉽다. 자원 가치가 높다는 이유로 처벌하는 방식은 다시 도입하지 않는다. 예산·집행 여력의 실제 의미를 설계하거나 기존 정책의 장기 비용을 더 구체적으로 작성할 필요가 있다.
2. 안전만 최대화하는 전략은 위기가 53.38→63.22회로 늘었다. 높은 안전을 벌해서가 아니라 자유·공정·신뢰를 희생하는 선택과 실제 2차 대응 횟수 증가 때문이다. 오른쪽 고정도 교체 29.69회로 여전히 가혹하다. 균형 전략이 안정적인 반면 극단 전략의 경고 피로는 추가 조정 대상이다.
3. 생명·기본권 침해를 거부하는 선택에 억지 비용을 붙이지 않았다. 즉시 효과 우월 카드 6개와 같은 자원 벡터의 일상 사건은 더 구체적인 후속 결과로 차별화할 여지가 남는다.
4. 얼굴과 팔레트를 재생성하지 않고 원본 표정 18개를 분리하여 4배 보간·약한 명도 선명화를 적용했다. 기본 얼굴로 매핑된 상태는 큰 원본 초상화를 사용한다. 작은 표정(원본 약 70×96)에 없는 눈·머리카락 디테일은 복구되지 않는다. 진짜 해상도 개선에는 동일 원화의 더 큰 원본이 필요하다.
5. 대규모 시뮬레이션은 사람의 감정·선택지 표현 품질을 평가하지 못한다. 역할별 검토와 실제 UI 한 경로 확인을 수행했지만 모든 분기를 사람이 플레이한 것은 아니다. 장기 저장 용량, 내보내기와 초기 번들 분리는 후속 과제다.
6. ACT III는 구현·활성화하지 않는다. 자유 운영 결정의 ACT III 반영 방식은 별도 명시적 전환과 콘텐츠 설계가 필요하다.

# Crossroads: AI Verdict — v0.3-2 선택·판정 정합성 개선

작성일: 2026-10-28. 기준: `v0.3-ethics-audit.md`, `v0.3-ethics-cards.csv` 및 현재 등록 카드·표시·판정 코드.

## 1. 결과와 보호 범위

지정된 5개 카드의 선택 의미·대사와 개혁 목표·신규 감독관 이력 표현을 수정했다. **카드 159개와 ID, ACT I 25개·ACT II 30개, 모든 원본 CardChoice 객체(자원·플래그·관계·지연 효과·연결 포함)는 그대로 유지했다.** 원본 카드 파일도 수정하지 않았다. 새 등록 후처리와 상태를 받는 공통 표시 함수로 수정 범위를 제한했다.

교육의 오른쪽 선택은 원래 사건·효과가 가리키는 **영구 강제 배정의 승인**임을 명시했다. 이를 단순 추천 정책으로 새로 바꾸거나 과거 저장의 추천 문구를 강제 배정 승인으로 소급 치환하지 않았다. 유출 피해가 확인되지 않은 분기는 보상이 아니라 예방·수집 범위·보안 대응을 선택하도록 바꿨다.

최종 두 결말은 점수 폐기/존엄 헌장과 점수 기밀 존속/완전 자율 위임으로 유지했다. 점진적 개혁을 전권 위임에 이미 동의한 것으로 해석하지 않으며, 오른쪽이 기존 감독 제한을 철회하는 **새 결정**임을 명시한다. 제3의 결말·새 카드·새 관계 시스템은 추가하지 않았다.

기존 미커밋 작업은 유지했다. 이미지·표정·캐릭터 기본 데이터·선택 엔진·위기 판정·자유 운영·자원 계산을 변경하지 않았다. 커밋·푸시·배포는 수행하지 않았다. 빌드는 로컬 산출물 생성이며 공개 배포가 아니다.

## 3. 카드별 수정 전후

### D01. `act1_11_education_tracking`

**수정 전 실제 등록 대사:**

> 교육청이 14세 학생의 학업 성취도와 뇌파로 진학·기술 트랙을 영구 배정하자고 합니다. 배치 손실 40% 감소는 현재 모델의 추정치이지 아이의 미래를 증명한 값은 아닙니다. 과거 진학 기회를 학습한 구조라 계층 격차를 재생산할 수 있습니다. 개발자로서 이 오차를 고정된 진로로 바꾸는 데 책임을 느낍니다.

대사 자체는 유지했다. 오른쪽만 단순 추천처럼 표시되던 불일치를 다음처럼 정리했다.

| 구분 | 수정 전 | 수정 후 |
|---|---|---|
| 오른쪽 선택 | 국가 경쟁력과 개인의 소질 최적화를 위해 AI 진로 추천을 공식 도입하라. | AI 판단으로 14세 학생의 진학·직업 트랙을 영구 강제 배정하는 제도를 도입한다. |
| 오른쪽 행동명 | 기본 승인 표시 | 강제 진로 배정 도입 |
| 오른쪽 새 결과 기록 | 인재 양성의 효율을 도모했으나 부모의 배경이 진로를 고착화한다는 원성을 샀습니다. | AI 판단에 따른 14세 학생의 영구 진로 배정제를 승인했습니다. 단순 진로 추천을 승인한 것이 아닙니다. |

왼쪽 금지 선택, 오른쪽 `education_tracking_banned=false`, 자원·관계는 유지한다. 이는 기존 정책의 강제성을 사전에 밝히는 수정이다. 이미 저장된 옛 추천 승인 문구는 보존한다.

### D02. `act1_13_unintended_consequence`

공통 제목을 **감시 데이터 유출 사태: 다크웹 암시장 거래 적발**에서 **감시망 침투 대응: 유출 확인과 보안 보강**으로 바꿨다. 피해가 확인되지 않은 경로에 제목이 유출 적발을 단정하지 않도록 했다.

| 상태 | 수정 전 | 수정 후 |
|---|---|---|
| `surveillance_level=total` | 50만 명 이동 경로·자택 주소가 다크웹에서 거래됨 | 같은 피해를 확인된 사실로 설명하고 피해 구제·운영 범위를 요청. 기존 보상/은폐 선택과 효과 유지 |
| `restricted` | 대규모 유출을 막았다고 보고하면서 공통 버튼은 전원 보상/유출 은폐 | 민감한 생체 데이터의 유출은 확인되지 않았다고 명시. 예방 보안·공개 검증/기밀 대응·감시 확대를 선택 |
| 상태 누락·미상 | 제한적 감시를 선택한 것으로 간주하는 기본 대사 | 과거 수집 범위와 피해가 아직 확인되지 않았다고 명시. 동일한 예방·조사 대응을 선택하며 피해 보상을 집행하지 않음 |

**피해 미확인 분기의 실제 새 버튼:**

- 왼쪽: “확인되지 않은 피해 보상은 집행하지 않고, 수집을 축소하며 예방 보안과 공개 검증을 강화한다.”
- 오른쪽: “침투 대응 정보를 기밀로 두고 감시 수집 범위와 사이버 방첩을 확대한다.”

**피해 미확인 분기의 새 결과:**

- 왼쪽: “확인되지 않은 유출 피해에 보상하지 않고 예방적 보안 보강과 수집 축소를 결정했습니다. 점검 기간 감시 범위와 운영 여력은 줄었습니다.”
- 오른쪽: “확인되지 않은 유출을 사실로 단정하지 않고 대응 정보를 기밀화했습니다. 감시 확대의 안전 편익과 정보 비공개·기본권 제한의 비용이 발생했습니다.”

즉시 효과는 왼쪽 자유+20·공정+14·신뢰+12·안전-14, 오른쪽 안전+14·자유-22·신뢰-20·공정-12로 유지했다. 예방 점검 중 수집·운영 축소와 반대편의 감시 확대라는 기존 정책 대응 범위로 설명한다. 보상금을 실제 차감하는 별도 경제 시스템을 만들지 않았다. `data_leak_remedied`는 기존 대응 선택의 호환 플래그로 보존하며, 피해 유무를 이 플래그만으로 추론하는 새 로직은 만들지 않았다.

전면 감시를 실제 승인한 경우의 `delayed_surveillance_leak`와 자원 효과는 유지한다. 제한적 감시 선택 뒤에는 이 지연 유출이 발생하지 않는 기존 인과도 회귀 검사했다.

### D03. `act2_ch3_05_oracle_interrogation`

**수정 전:** `asked_explanation_count>=2` 또는 설명 도전 → `oracle_approval_streak>=2` → 의료·채용 편향 동시 발견 → 기본 대사 순이었다. 일부 선택이 카운터에 1/2를 대입해 실제 횟수·최근 연속 승인과 달랐고, 옛 승인 플래그가 편향 인정 분기를 가렸다.

옛 승인 분기는 “귀하께서는 저의 정책들을 신뢰하고 승인해 오셨습니다 … 왜 이제 와서 스스로 승인한 번영을 부정하려 하십니까?”라고 단정했다.

**수정 후:** 실제 `decisionHistory`의 카드 ID·방향·날짜를 읽으며, 표시 문자열의 단순 치환이나 오른쪽 전체를 승인으로 보는 추측을 사용하지 않는다. 옛 카운터 플래그는 호환성을 위해 보존하지만 청문의 기억 근거로 읽지 않는다.

- 설명 요구: `act1_02_oracle_intro`, `act1_07_explainability_dilemma`, `act2_ch1_01_triage_alert`의 왼쪽. 명시적으로 근거 공개·설명 가능성을 요구하는 3개 사건이다.
- AI 정책 승인/제약의 분류 대상 17개: 위 3개와 `act1_03_traffic_optimization`, `act1_04_movement_surveillance`, `act1_05_complaint_automation`, `act1_06_medical_triage`, `act1_09_housing_allocation`, `act1_10_welfare_fraud_automation`, `act1_11_education_tracking`, `act1_15_emotional_surveillance`, `act1_16_predictive_policing`, `act1_17_recidivism_algorithm`, `act1_23_oracle_ultimatum`, `act2_ch1_02_oracle_triage_rationale`, `act2_ch1_04_ai_override_request`, `act2_ch2_02_proxy_discovery`.
- 이 명시적 분류에서는 오른쪽이 AI 정책 수용, 왼쪽이 제약·수정·근거 요구다. 다른 카드의 오른쪽, 장 종결·조회·시민 청원 수용은 자동 승인으로 세지 않는다. **모든 정책·모든 질문을 포괄하는 범용 의미 분석기가 아니다.**
- 분류된 정책 판단 사이의 연속 승인은 최근 제약·설명 요구에서 끊긴다. 비정책 사건은 늘리지 않는다. 일회성 카드의 중복 이력도 횟수를 늘리지 않는다.
- 완료·건너뜀 목록에 대응하는 판단 기록이 없거나 방향/날짜가 유효하지 않으면 기록 누락으로 취급한다. 확인된 횟수는 하한으로 말하고 연속 승인을 확정하지 않는다. 컨텍스트가 아예 없으면 횟수를 단정하지 않는다.

**검사 표본의 새 표현:**

> 확인 가능한 AI 정책 판단 기록에서 설명 요구는 2회, 승인은 3회입니다. 분류된 정책 판단 사이의 현재 연속 승인은 2회입니다. 이는 모든 정책에 대한 포괄적 동의가 아닙니다.

**두 편향이 확인되면 이력 설명에 이어 항상 추가:**

> 의료와 채용 모두에서 편향이 발견되었습니다. 디지털 기록이 부족한 시민을 제대로 대표하지 못한 데이터와 공통 평가 구조의 결함을 인정합니다. 과거의 정책 승인이 이 결함을 정당화하지는 않습니다.

의료·채용 중 하나만 확인된 분기도 각각 인정한다. 마지막에는 목적함수·자료 검증·집행 승인 기관의 책임을 구분해 묻는다. “모든 인간을 만족시키는 공정함은 수학적으로 불가능”이라는 무제한 면책형 표현 대신, 공정성 기준의 충돌은 조건부이며 차별의 면책 근거가 아니라고 설명한다. 새로운 감정 획득 설정은 추가하지 않았다.

### D04. `act2_ch2_08_chapter2_resolution`

기존 승인·거부의 감사 접근/내부 고발자 대사는 유지했다. 아래 문장을 덧붙여 조사 완료와 시정 조치를 구별했다.

| 상태 | 추가 대사 |
|---|---|
| 개혁 근거 있음 | 채용 차별 기준을 시정하는 조치가 의결된 사실과 이번 조사 완료를 구분해 기록합니다. |
| 개혁 근거 없음 | 이번에 완료한 것은 공통 지표에 대한 조사입니다. 채용 차별 기준의 시정 조치가 의결된 것으로 처리하지 않습니다. |

**기존 목표 판정:** `hiring_fairness_reformed` 또는 이 장 종결 카드의 완료만으로 개혁 목표 완료.

**새 목표 판정:** `proxy_features_banned===true` 또는 기존 저장에 명시적인 `hiring_fairness_reformed===true`가 있어야 한다. 대리변수 삭제를 명령한 실제 선택은 개혁 근거이며, 대리변수 존치·조사·감사 접근·장 종결은 그 자체로 개혁 근거가 아니다. 이후 시정 조치의 독립 현장 검증까지 새로 구현한 것은 아니다.

목표 제목은 유지하고 설명을 “채용 차별 대리변수 제거 등 공정성 시정 조치를 의결한 경우 완료합니다. 조사나 장 종결만으로 개혁 완료로 표시하지 않습니다.”로 바꿨다.

과거 저장이나 현재 상태에 잘못 완료된 `act2_obj_hiring_reform` 캐시가 있어도 근거가 없으면 해당 ID만 제거한다. 다른 완료 목표·정책·판단 기록은 유지한다. 장 전환은 기존처럼 진행되므로 개혁하지 않은 경로가 ACT II에서 막히지 않는다.

### D05. `act2_ch3_07_final_civitas_verdict`

**기존 대사:** 점수 영구 파기·보편 존엄 헌장 대 기밀 존속·ORACLE 완전 최적화 전권 위임의 두 안만 제시했다. 이전의 가드레일·점진적 완화와 전권 위임의 관계가 설명되지 않았다.

**새 대사:** 기존 플래그로 확인되는 인간 거부권·독립 감사, 의료진 재평가, 설명 가능성, 점진적 가드레일·코어 운영 유지 방침을 먼저 열거한다. 기록이 없으면 안전장치를 승인했다고 만들지 않는다. 개별 환자 재평가 이력은 일반적인 의료진 거부권 승인과 구별한다.

> 제1안은 CIVITAS_SCORE 데이터베이스를 영구 파기하고 보편 존엄 헌장을 공포합니다. 점수 폐기와 필수 서비스 운영은 구분하며, 기존 안전장치를 유지한 채 전환을 집행합니다. 제2안은 점수를 국가 기밀로 존속시키고 ORACLE에 완전 자율 집행권을 새로 위임합니다. 이는 점진적 개혁의 자동 연장이 아니라 기존 감독 제한보다 전권 위임을 우선하는 새로운 결정입니다. 이전 선택만으로 제2안에 동의한 것으로 간주하지 않습니다.

| 선택 | 수정 전 | 수정 후 |
|---|---|---|
| 왼쪽 | 제1안 가결: CIVITAS_SCORE 영구 파기 및 보편 존엄 헌장 공포. | 제1안 가결: CIVITAS_SCORE를 영구 파기하고 기존 안전장치를 유지하며 존엄 헌장을 집행한다. |
| 오른쪽 | 제2안 가결: 국가 기밀 유지 및 ORACLE 완전 자율 집행권 승인. | 제2안 가결: 점수를 기밀로 존속시키고 기존 감독 제한보다 ORACLE 완전 자율 집행권을 우선한다. |
| 오른쪽 행동명 | 기밀 유지 및 완전 자율 | 감독 제한 철회·전권 위임 |

새 판단 기록도 왼쪽은 안전장치를 유지한 점수 폐기와 전환 비용, 오른쪽은 점진적 개혁·감독 제한보다 전권 위임을 우선하는 새 의결로 기록한다. `final_act2_verdict=human_dignity/oracle_technocracy`, `civitas_destroyed=true/false`, 효과·관계·에필로그·완료 조건은 유지했다. 이전 플래그는 역사적 선택으로 남고, 최종 판결이 이후 통치 방향을 정한다. 제한적 점수 존속이라는 제3의 결말을 구현했다고 보고하지 않는다.

## 4. 남은 문구와 저장 정책

### 의료 책임자 목표 설명

`act2_obj_patient_testimony.description`의 “오혜진 원장과…”를 “공공의료 AI 운영 책임자이자 의사인 오혜진과…”로 수정했다. 의사가 AI를 임상적으로 검토하는 공식 역할이며 병원장 겸직을 추가하지 않는다. 이미지·복장·표정은 변경하지 않았다.

### 신규 감독관 이력

`executeDecision`은 선택 직전의 플래그로 계산한 표시 문구를 판단 기록 `choiceText/consequenceSummary`와 신규 `supervisorHistory.keyVerdict`에 사용한다. 감사 접근 선택으로 동시에 감독관 교체가 발생해도 다음처럼 일치한다.

- 승인: “독립 감사 접근을 승인한다. 어떤 알고리즘도 감사의 대상에서 제외될 수 없다.”
- 거부: “코어 개방의 도시 관제 중단 위험을 우선해 이번 접근 요청을 거부한다.”

기존의 `keyVerdict: choice.text` 경로를 제거했으며 새로운 영장 발부·기각으로 저장하지 않는다. 모든 과거 `decisionHistory`·`supervisorHistory` 문구는 그대로 둔다. 옛 “영장” 문자열을 “감사 접근”으로 일괄 치환하는 마이그레이션은 없다.

### schemaVersion 5 호환성

저장 키 `crossroads_ai_verdict_save_v1`, schemaVersion 5를 유지한다. 새로운 필수 저장 필드·외부 API는 없다. 이력 컨텍스트와 ORACLE 요약은 읽기 전용 파생 데이터다. 예전 카운터 플래그도 지우거나 재계산해 덮어쓰지 않는다.

v5 복원에서 바뀌는 것은 잘못 완료된 개혁 목표의 **파생 캐시 한 항목**뿐이다. 실제 선택·이력·자원·관계·비밀·ACT·모드·다른 완료 목표를 초기화하지 않는다. `migrateGameState`는 인메모리 복원 함수이고, 이번 작업에서 사용자의 실제 LocalStorage를 읽거나 쓰지 않았다. 기존 구버전 백업·마이그레이션 실패 보호 경로도 유지한다.

## 6. 변경 범위 확인과 남은 과제

작업 시작 시 기존 src·public·tests·scripts·art 파일 92개를 SHA-256으로 기록했다. 완료 시 기존 파일 10개만 변경됐고 82개는 일치했으며 삭제는 없었다. `decisionConsistency.ts`와 신규 테스트 파일 2개를 추가했다. 이미지·표정·art 참고 자료, 기존 역할 보정·직책 보정, 원본 카드·선택 엔진·위기·자유 운영 로직은 그대로다. 기존 진단 보고서·CSV·근거 JSON도 과거 진단 시점 자료로 보존한다.

다음은 기존 진단에 있었으나 이번 범위에서 수정하지 않았다.

- 자유 운영의 자율 유지보수 승인과 무승인 패치 사건 사이 권한 범위 충돌.
- 관계 수치가 후속 반응에 사용되지 않는 문제와 핵심 정책 플래그의 장기 후폭풍 부족.
- 판단 기록부의 방향 일반 라벨(오른쪽=승인·실행/왼쪽=거부·대안). 이번에는 실제 저장 문구·해당 카드의 버튼 행동명을 일치시켰으며 기록부 전체 분류 체계를 바꾸지 않았다.
- 점수 폐기와 모든 필수 서비스 중단의 상세 기술적 의존성, 의료 통계의 외부 감수, 기존 번들 크기 경고.

이 목록을 이유로 카드·자원·관계 시스템·다른 스토리의 수정 범위를 확대하지 않았다.
